\section{QuorumShift Engine Architecture}
\label{sec:methodology}

The QuorumShift architecture decouples Phase 1 leader election quorums from Phase 2 log commit quorums using continuous telemetry-driven dynamic weighting.

\subsection{Dynamic Node Weighting Formulation}
Each node $i$ is assigned a dynamic weight $W_i(t)$ based on its real-time round-trip latency $\text{RTT}_i$ and packet loss rate $L_i$:
\begin{align}
    W_i(t) = \frac{1.0}{1.0 + \alpha \cdot \max(0, \text{RTT}_i - \text{RTT}_{\text{base}}) + \beta \cdot L_i}
\end{align}
where $\alpha = 0.05$ and $\beta = 2.0$ are penalty coefficients, and $\text{RTT}_{\text{base}} = 2.0\,\text{ms}$.

\subsection{Phase 2 Commit Verification}
For a candidate set of acknowledging nodes $A \subseteq \{1, \dots, N\}$, a log entry commit is satisfied if:
\begin{align}
    \sum_{i \in A} W_i(t) \ge \Theta_{\text{dynamic}} \cdot \sum_{j \in H} 1.0
\end{align}
where $\Theta_{\text{dynamic}} = 0.35$ and $H$ denotes the set of healthy active cluster nodes.

\subsection{Safety Guarantee}
Because Phase 1 leader elections still require a static majority $Q_1 = \lfloor N/2 \rfloor + 1$, the intersection condition $Q_1 \cap Q_2(t) \neq \emptyset$ holds universally, guaranteeing zero stale reads and strict linearizability.
